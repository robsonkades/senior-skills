# HCM analysis depth extension

Date: 2026-10-04. Scope: nine existing skills, updated from 1.0.0 to 1.1.0 after the one-time
initial version reset. The catalog still has 32 skills. The other 23 skills and all software
package versions remain 1.0.0. Skill identifiers remain appropriate: each extension deepens its
existing responsibility instead of creating a competing HCM-specific owner.

## Implemented content

| Responsibility                        | Changed skills                                                    | Applied addition                                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Business rules                        | `collaborative-feature-definition`, `requirements-and-acceptance` | Conditional route to one authoritative decision-table method; precedence, unknowns, policy time and filled cases. |
| Source data and destination agreement | `feature-context-analysis`, `feature-contract-definition`         | Scoped profiling, de/para lifecycle and reconciliation with equal-count counterexamples.                          |
| Estimates and delivery preparation    | `feature-solution-analysis`, `feature-decomposition`              | Comparable owner-supplied responses, scope/revision inputs, nonoverlapping work and effort versus elapsed time.   |
| Activation and support                | `feature-implementation-plan`, `feature-readiness-review`         | Rehearsal, load/change continuity, uncertain effects, correction/support ownership and stage-specific evidence.   |
| Connected analysis and adoption       | `feature-engineering`                                             | Full fictional benefits case, cross-meeting resumption and an observational pilot protocol.                       |

Methods and templates are in English. Worked cases contain synthetic identifiers and clearly
fictional policies/contracts. The customer workbook and Connect PDF were not changed or treated
as evidence of a deployed capability. No customer/environment action was performed.

The [usage guide](hcm-business-analysis.md#use-the-deeper-methods-when-the-decision-needs-them)
links the authoritative references. The existing checklist and Connect context remain the intake
and product-investigation path; the additions consume their evidence rather than duplicate them.

## Validation and remaining evidence

The [targeted evaluation report](evaluations/hcm-depth/results.md) records the frozen inputs,
resource hashes, actor exposure, observed responses and individual criteria. The available actors
were reused collaborators. These runs can reveal failures in the exercised cases, but do not
establish improvement caused by the skills, automatic selection quality or real-team productivity.

Repository checks cover packaging, descriptions, dependency resolution, generated registry and
tests. Version changes are compared explicitly to the preserved pre-edit snapshot because this
workspace has no Git history. Report any unrelated failing or unavailable checks rather than
claiming that the entire verification command passed.

The highest-value next evidence is a real analyst pilot using an authorized demand and applicable
Senior/provider contracts. Record actual corrections, returned issues and observed acceptance.
The protocol is implemented; customer participation, live homologation and adoption measurements
remain outside the evidence obtained here.
